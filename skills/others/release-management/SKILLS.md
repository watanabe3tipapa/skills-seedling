# Release Management

変更を利用者に安全に届け、必要なら戻せるようにするためのスキル。

## いつ使うか

- リリース手順やバージョン番号を決めるとき
- チェンジログやタグを作成するとき

## 基本方針

- セマンティックバージョニングで破壊的変更を明示する
- チェンジログは利用者視点で書く（変更点と影響）
- リリースは再現可能な手順（自動化）にする
- ロールバック手順を常に用意する

## 進め方

1. 前回リリースからの変更を洗い出す
2. バージョンとチェンジログを決める
3. タグ付けし、手順どおりにリリースする
4. リリース後、監視とロールバック可能性を確認する

## チェックリスト

- [ ] 破壊的変更を明記したか
- [ ] チェンジログが利用者視点か
- [ ] リリース手順が再現可能か
- [ ] ロールバック手順があるか
- [ ] タグとバージョンが一致しているか
