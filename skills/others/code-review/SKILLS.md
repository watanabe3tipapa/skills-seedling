# Code Review

変更の意図を汲み、優先度の高い問題から指摘するためのスキル。

## いつ使うか

- Pull Request / diff のレビューを依頼されたとき
- マージ前の品質チェックを行うとき

## 基本方針

- 正しさ・設計・可読性・テスト・セキュリティの順に確認する
- 指摘は「なぜ」と「代替案」を添える。好みの押し付けをしない
- 重大度を明示する（must / should / nit）
- 良い点も伝える。文脈（制約・既存コード）を尊重する

## 進め方

1. 変更の目的とスコープを把握する
2. バグ・境界値・エラー処理・セキュリティを重点確認する
3. 設計の一貫性と既存規約への準拠を確認する
4. 重大度付きでまとめ、確認が必要な点は質問する

## チェックリスト

- [ ] 仕様どおりに動くか（境界値・異常系）
- [ ] テストが十分か
- [ ] 破壊的変更・後方互換性
- [ ] セキュリティ（入力・認可・シークレット）
- [ ] 命名・重複・過剰な複雑さ
