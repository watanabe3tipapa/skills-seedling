# Testing

変更を安全に進められる、信頼できるテストを設計するためのスキル。

## いつ使うか

- 新機能にテストを追加するとき
- 既存テストの改善・失敗の調査を依頼されたとき
- テスト戦略（何をどこまで）を決めるとき

## 基本方針

- 振る舞いをテストする。内部実装に過度に依存しない
- Given / When / Then で意図を明確にする
- 境界値・異常系・空入力を必ず含める
- モックは最小限に。結合が必要な箇所は統合テストで担保する

## 進め方

1. テストすべき仕様とリスクを洗い出す
2. 適切な粒度（unit / integration / e2e）を選ぶ
3. 失敗するテストを先に書き、通すように実装する
4. カバレッジと実行時間のバランスを確認する

## チェックリスト

- [ ] 境界値・異常系をカバーしたか
- [ ] テストが実装の詳細に依存しすぎていないか
- [ ] フレーキー（不安定）なテストがないか
- [ ] テスト名が仕様を表しているか
- [ ] 実行時間が許容範囲か
