# Git Workflow

履歴を読みやすく保ち、安全に変更を統合するためのスキル。

## いつ使うか

- ブランチ運用やコミット方針を決めるとき
- コンフリクト解消・履歴整理を行うとき

## 基本方針

- 1コミット1目的。メッセージで「なぜ」を書く
- 共有ブランチの履歴は書き換えない
- 統合は小さく頻繁に。長命なブランチを避ける
- 破壊的操作（force push 等）は慎重に、影響範囲を確認する

## 進め方

1. チームのブランチ戦略と命名規約を確認する
2. 変更を論理単位でコミットする
3. レビュー前に diff と履歴を整理する
4. コンフリクトは意図を確認して解消する

## チェックリスト

- [ ] コミットが論理単位に分かれているか
- [ ] メッセージが「なぜ」を説明しているか
- [ ] シークレットや生成物をコミットしていないか
- [ ] 共有履歴を書き換えていないか
- [ ] 巨大な diff になっていないか
