# Prompt Engineering

AI コーディング支援ツールや LLM への依頼文を、意図どおりの出力を得られるように設計・改善するためのスキル。

## いつ使うか

- プロンプトを新規に書くとき、既存のプロンプトの出力が期待外れのとき
- エージェント用の指示文（AGENTS.md / CLAUDE.md / スキル定義）を書く・直すとき
- 長い作業の指示を分割・構造化する必要があるとき

## 基本方針

- 目的・制約・出力形式を明示する（暗黙の期待に頼らない）
- 背景は必要な分だけ、雑談は書かない — コンテキストは精度とコストの両方に効く
- 一度に詰め込まず、単一の概念ごとに分ける
- 抽象的な指示（「良い感じに」）は具体例または評価基準に置き換える
- 人間が読むことばは自由、機械が読む契約（構造・スキーマ）は正規化する

## 進め方

1. 出力の目的を一文で書く（誰が、何に使うか）
2. 制約条件を列挙する（やってよいこと・いけないこと、技術スタック、既存規約）
3. 出力形式を指定する（ファイル構成、トーン、スキーマ）
4. 例を 1 つ添える（正例を基準にし、負例の羅列は避ける）
5. 出力を評価し、ズレた点を次の依頼に反映して反復する

## チェックリスト

- [ ] 目的と成功条件が一文で言えるか
- [ ] 制約が列挙されているか（技術・形式・禁止事項）
- [ ] 出力形式が指定されているか
- [ ] 必要なコンテキストだけを渡しているか（過剰・過少がないか）
- [ ] ズレた出力に対して、指示を追加するのではなく原因を特定したか

## ことばの対応

- コンテキストエンジニアリング ＝ プロンプト単体だけでなく、渡す情報の選定・構造化まで含めた設計
- 意図アンカー — 本文の見出しに付ける `{#when}` などの識別子。機械が意味に到達できるようにするため
