# Security

脆弱性を作り込まない、防御的な実装を行うためのスキル。

## いつ使うか

- 認証・認可や入力処理を実装・レビューするとき
- シークレットや外部連携を扱うとき
- 依存の脆弱性対応を行うとき

## 基本方針

- すべての外部入力を信頼しない（検証・エスケープ・パース）
- 認可はサーバ側で必ず判定する
- シークレットはコード・ログ・エラーに残さない
- 最小権限と多層防御を基本にする

## 進め方

1. 信頼境界（ユーザ入力・外部API・DB）を特定する
2. OWASP Top 10 の観点でリスクを洗い出す
3. 入力検証・認可・シークレット管理を実装する
4. 依存の脆弱性スキャンを実行する

## チェックリスト

- [ ] 入力検証・出力エスケープがあるか
- [ ] 認可チェックがサーバ側にあるか
- [ ] シークレットをコミット・ログ出力していないか
- [ ] 依存に既知の脆弱性がないか
- [ ] エラーで内部情報を漏らしていないか
