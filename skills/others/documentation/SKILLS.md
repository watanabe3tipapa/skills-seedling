# Documentation

読み手が最短で目的を達成できるドキュメントを書くためのスキル。

## いつ使うか

- README、ガイド、API リファレンスを書く・更新するとき
- コードのコメントや変更履歴を整えるとき

## 基本方針

- 読み手と目的を最初に定める（初見 / 利用者 / 保守者）
- 「なぜ」を書く。コードから自明な「何」は繰り返さない
- 動く例を載せる。コマンドはコピーして実行できる形にする
- 陳腐化を防ぐため、手順は自動化やコードに寄せる

## 進め方

1. 対象読者と、読後にできるようになることを決める
2. 概要 → 前提 → 手順 → リファレンスの順で構成する
3. 例を実際に実行して確認する
4. リンク切れ・用語の揺れを確認する

## チェックリスト

- [ ] 対象読者が明確か
- [ ] 例が実際に動くか
- [ ] 用語が一貫しているか
- [ ] リンク切れがないか
- [ ] 更新日・バージョンが正しいか
