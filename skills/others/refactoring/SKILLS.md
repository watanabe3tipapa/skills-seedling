# Refactoring

挙動を変えずに、コードを読みやすく変更しやすくするためのスキル。

## いつ使うか

- 重複や肥大化したコードの整理を依頼されたとき
- 変更しづらい箇所の改善や、テスト整備と合わせて行うとき

## 基本方針

- 挙動を変えない。変更の前後でテストが同じ結果になることを保証する
- 小さなステップで進め、各ステップでテストを緑に保つ
- 一度に多くの関心事を混ぜない
- リファクタと機能追加は別の変更に分ける

## 進め方

1. テストで現状の挙動を固定する（不足なら先に追加する）
2. 改善の目的（重複・責務・命名）を決める
3. 小さく変更し、都度テストを実行する
4. 差分を見直し、意図しない挙動変更がないか確認する

## チェックリスト

- [ ] テストで挙動を固定してから着手したか
- [ ] 挙動が変わっていないか
- [ ] リファクタと機能変更を混ぜていないか
- [ ] 可読性・責務が改善したか
- [ ] テスト・lint・型チェックが通るか
