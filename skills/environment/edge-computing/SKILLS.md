# Edge Computing

エッジ環境の制約を踏まえ、低遅延な処理を設計するためのスキル。

## いつ使うか

- CDN / エッジ関数（Workers / Edge Functions など）で処理を実装するとき
- 地理分散やキャッシュ戦略を設計するとき

## 基本方針

- エッジの制約（実行時間・メモリ・API 制限）を前提に設計する
- ステートレスを基本にし、状態は外部ストアに置く
- キャッシュと再検証（TTL / stale-while-revalidate）を設計する
- エッジとオリジンの責務を分ける

## 進め方

1. 目標遅延と対象地域、ランタイム制約を確認する
2. エッジで行う処理とオリジンに残す処理を分ける
3. キャッシュキーと無効化戦略を決める
4. 各リージョンでの挙動とフォールバックを確認する

## チェックリスト

- [ ] ランタイム制約内に収まっているか
- [ ] ステートレスに保っているか

- [ ] オリジン障害時のフォールバックがあるか
- [ ] シークレットの扱いは適切か
