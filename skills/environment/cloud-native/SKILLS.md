# Cloud Native

クラウドの特性を活かし、スケールと運用負荷のバランスを取るためのスキル。

## いつ使うか

- クラウドアーキテクチャを設計・見直しするとき
- マネージドサービスやサーバレスを選定するとき
- スケーリング、可用性、コストを最適化するとき

## 基本方針

- マネージドを優先し、運用負荷を減らす
- 単一障害点を作らない。リージョン/ゾーンを意識する
- 可観測性（ログ・メトリクス・トレース）を最初から設計に含める
- コストは設計時の制約として扱う

## 進め方

1. 要件（負荷・SLA・予算・コンプライアンス）を確認する
2. サービス選定と構成図を作る。トレードオフを明記する
3. IaC でプロビジョニングし、環境を再現可能にする
4. 監視・アラート・コスト監視を設定する

## チェックリスト

- [ ] 単一障害点がないか
- [ ] 権限は最小限か（IAM）
- [ ] ログ・メトリクス・トレースが揃っているか
- [ ] コスト見積もりをしたか
- [ ] 障害時のリカバリ手順があるか
