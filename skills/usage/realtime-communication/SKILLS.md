# Realtime Communication

切断と再接続を前提に、リアルタイム通信を堅牢に組むためのスキル。

## いつ使うか

- チャット・通知・共同編集などリアルタイム機能を実装するとき
- 接続管理やスケーリングを設計するとき

## 基本方針

- 切断は必ず起きる前提で、指数バックオフ再接続を入れる
- メッセージの順序・重複・欠落を設計で吸収する（ID・ack・再送）
- クライアント状態とサーバ状態の整合方法を決める
- スケール時はファンアウト（Pub/Sub）を検討する

## 進め方

1. 同期要件（遅延許容・整合性・オフライン可否）を確認する
2. プロトコル（WebSocket / SSE / ポーリング）を選ぶ
3. 再接続・再同期・ACK を実装する
4. 切断・高負荷での挙動をテストする

## チェックリスト

- [ ] 自動再接続とバックオフがあるか
- [ ] 重複・順序・欠落への対処があるか
- [ ] 認証・認可が接続時に行われるか
- [ ] スケール時のファンアウトを考慮したか
- [ ] 切断時のUI状態が適切か
