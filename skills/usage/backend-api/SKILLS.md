# Backend API

サーバサイドAPIを、契約と境界を明確にして設計・実装するためのスキル。

## いつ使うか

- エンドポイントの追加・変更を依頼されたとき
- 入出力スキーマ、バリデーション、エラー形式を定義するとき
- 認証・認可、レート制限、ページングを扱うとき

## 基本方針

- APIは契約。入出力スキーマを先に決め、後方互換を壊さない
- バリデーションは境界（ハンドラ入口）で行い、内部は型で守る
- エラーは一貫した形式で返し、内部実装の詳細を漏らさない
- 認可は必ずサーバ側で判定する。クライアントを信用しない

## 進め方

1. 既存のAPI規約（命名・バージョニング・エラー形式）を確認する
2. リクエスト/レスポンスのスキーマとステータスコードを決める
3. ハンドラ → サービス → リポジトリの順に実装する
4. 正常系・異常系・境界値のテストを書く

## チェックリスト

- [ ] 入力バリデーションを境界で行っているか
- [ ] 認証・認可の判定がサーバ側にあるか
- [ ] エラー形式が既存と揃っているか
- [ ] 後方互換性を壊していないか
- [ ] N+1クエリや過剰なデータ返却がないか
- [ ] 型チェック・テストが通るか
