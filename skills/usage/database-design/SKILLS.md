# Database Design

データの整合性と性能を両立するスキーマ・クエリを設計するためのスキル。

## いつ使うか

- スキーマ設計やテーブル追加を依頼されたとき
- マイグレーションを書くとき
- 遅いクエリの改善を求められたとき

## 基本方針

- 制約（NOT NULL / UNIQUE / FK）で整合性をDB側で守る
- 正規化を基本に、必要箇所のみ意図的に非正規化する
- インデックスはクエリパターンに基づいて張る
- マイグレーションは後方互換・可逆を意識する

## 進め方

1. アクセスパターン（読み書きの頻度・条件）を洗い出す
2. スキーマと制約、インデックスを設計する
3. マイグレーションを前方・後方互換に配慮して書く
4. 実行計画（EXPLAIN）で性能を確認する

## チェックリスト

- [ ] 制約で整合性を守っているか
- [ ] インデックスが主要クエリに対応しているか
- [ ] N+1 を避けているか
- [ ] マイグレーションがデータを壊さないか
- [ ] 実行計画を確認したか
