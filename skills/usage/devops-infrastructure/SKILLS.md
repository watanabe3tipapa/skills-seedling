# DevOps / Infrastructure

ビルド・デプロイ・運用を自動化し、再現可能なインフラを保つためのスキル。

## いつ使うか

- CI/CD パイプラインの追加・修正を依頼されたとき
- Dockerfile、マニフェスト、IaC（Terraform 等）を扱うとき
- 監視・アラート・ロールバックなど運用自動化を設計するとき

## 基本方針

- 手順はコード化（IaC / スクリプト）し、手作業を残さない
- 変更は小さく、ロールバック可能な単位にする
- シークレットはリポジトリに置かず、シークレットストアから注入する
- 本番同等の環境で検証してから流す

## 進め方

1. 現行のパイプライン/インフラ構成と変更影響範囲を確認する
2. 変更を小さなステップに分割し、plan/dry-run で差分を確認する
3. 段階的に適用し、各段でヘルスチェックする
4. 監視・アラート・ロールバック手順を整える

## チェックリスト

- [ ] シークレットがコード・ログに露出していないか
- [ ] ロールバック手順があるか
- [ ] 権限は最小限か
- [ ] 冪等に実行できるか
- [ ] 監視・アラートの対象に含めたか
