# Observability

本番で「何が起きているか」を把握できる計装を入れるためのスキル。

## いつ使うか

- サービスの計装（ログ・メトリクス・トレース）を追加するとき
- アラートやダッシュボードを設計するとき

## 基本方針

- 構造化ログ（JSON）で、機械的に検索できるようにする
- 相関 ID / trace ID をリクエスト全体で引き回す
- 計測は症状ではなく原因を切り分けられる粒度にする
- アラートは「行動が必要なもの」だけにする

## 進め方

1. 監視したい症状（遅延・エラー・飽和）を決める
2. ログ・メトリクス・トレースの役割分担を決める
3. 計装し、機密情報がログに出ないことを確認する
4. ダッシュボードとアラート閾値を整える

## チェックリスト

- [ ] ログが構造化され、相関 ID を持つか
- [ ] 個人情報・シークレットをログに出していないか
- [ ] エラーが握りつぶされていないか
- [ ] アラートに閾値と対処手順があるか
- [ ] 計装のオーバーヘッドが許容範囲か
