# C

未定義動作を避け、境界と資源の寿命を明示するコードを書くためのスキル。

## いつ使うか

- C の実装・修正・レビューを依頼されたとき
- 組込み、システム、ライブラリ、性能が要る処理を書くとき

## 基本方針

- 未定義動作を避ける。境界・初期化・寿命を常に意識する
- 確保と解放を対にする。所有権（誰が `free` するか）を決めてから書く
- 境界チェックを怠らない。`strcpy` より長さを取る API を選ぶ
- 警告は失敗として扱う。`-Wall -Wextra -Werror` を前提にする

## 進め方

1. 対象の標準（C11 / C17）とツールチェーンを確認する
2. データの所有権と寿命（確保・解放の責務）を決める
3. 境界チェックとエラー処理を実装する
4. `-fsanitize=address,undefined` とテストで検証する

## チェックリスト

- [ ] バッファ境界を検証しているか
- [ ] `malloc` に対応する `free` があるか
- [ ] 初期化前の読み取りがないか
- [ ] 符号付き/符号なしの混在演算に注意しているか
- [ ] 警告ゼロでビルドできるか
