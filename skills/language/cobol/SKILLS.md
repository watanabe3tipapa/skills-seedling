# COBOL

既存資産を尊重し、桁と境界を明示して保守するためのスキル。

## いつ使うか

- COBOL の実装・修正・レビューを依頼されたとき
- 基幹系、バッチ処理、既存資産の改修をするとき

## 基本方針

- 既存のコーディング規約と命名を尊重する
- `PIC` 句の桁・符号と桁あふれ・丸めを常に意識する
- 内部形式（`COMP-3` など）と文字コードを確認する
- 新規に `GO TO` を増やさず、変更は最小限に留める

## 進め方

1. 書式（固定 / 自由）とコンパイラ・実行環境を確認する
2. データ定義（`PIC` 句 / コピーブック）を確認する
3. 変更を最小限に留めて実装する
4. コンパイルとテストケースで回帰を検証する

## チェックリスト

- [ ] `PIC` 句の桁と符号が正しいか

- [ ] 既存の規約から逸脱していないか
- [ ] テストケースで回帰を確認したか
