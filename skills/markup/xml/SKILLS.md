# XML

整形式と名前空間を守り、スキーマで検証できる XML を書くスキル。

## いつ使うか

- XML を書く・直す・検証するとき
- 設定、データ交換、文書のマークアップを扱うとき

## 基本方針

- 整形式（well-formed）を守る。タグは正しく閉じる
- 名前空間を明示し、要素名の衝突を避ける
- 予約文字をエスケープする
- 外部実体参照や DTD を安易に使わない（XXE 対策）

## 進め方

1. 用途（データ / 設定 / 文書）とスキーマを確認する
2. 名前空間と要素設計を決める
3. 実装する
4. パーサ / バリデータで検証する
